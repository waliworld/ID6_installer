v0.3.0

One guided procedure for BMW NBT Evo (iDrive 5/6) head units: enable SSH, identify the unit, install the BoostDeck / ShiftDeck / MHD Maps gauges, and turn on full-screen CarPlay — then close SSH back up. Everything runs locally over the cable in your car.

Before you start — what you need
  • Car parked, ignition on, iDrive fully awake, and kept awake the whole time.
  • A wired ENET (OBD-to-Ethernet) cable to this computer; adapter should show a 169.254.x.x address.
  • This runs on NBT Evo 007.xxx units. Do not run the SSH step on a 001_05x unit.
  • Gauge install also needs a supported HMI build (NBTevo_N18092I / V20153I / Y24073J); the Identify step checks this.

This is a parked preview. Verify gauges, map switching and CarPlay on the car before relying on them.

Step 1

Connect & find your car

Plug in the ENET cable, then press Find my car. If only the gateway fills in, enter the head-unit IP.

Step 2

Enable SSH / OPT_DEBUG

On NBT Evo, enabling SSH is flipping OPT_DEBUG (STOP→RUN) in starter.cfg — one mechanism: after a reboot sshd/telnet/qconn come up as root. Reverts in Step 6. EntryNav2 is a different unit — it roots another way (root password), so this step is NBT-Evo-only.

This writes to a live partition and can disable the head unit if it's the wrong type. Only run on an NBT Evo 007.xxx unit. If anything goes wrong, use Close SSH / Restore factory (Step 6) first; serial/eMMC is the last resort.

After the flash the unit reboots (~50s); SSH comes up as root. Keep the cable connected.

Step 3

Identify the unit

Read-only. Confirms the firmware, display and framework match, lists installed apps, and decides which CarPlay method your unit needs. Enter the root password only if your SSH step set one (left blank for key/no-password units).

Step 4

Install the gauges

Installs BoostDeck, ShiftDeck and MHD Maps, keeping a backup of anything replaced. Keep iDrive on and the cable connected.

Step 5

Full-screen CarPlay

What's needed depends on your firmware — the Identify step decides this for your unit.

Full-screen CarPlay is the coding bit CARPLAY_FULLSCREEN (dg3000/byte39/bit7), for cars that already have CarPlay. The toolbox resolves the coordinate and backs up coding first; the signed write runs from Coding & FSC below (needs PSdZData + consent).
My unit has no CarPlay at all

CarPlay activation is real now, backed by the MIT nbt-evo-toolkit: mint the CarPlay FSC (0x0143) under your own trust anchor, install your blobB, apply it, and set the CARPLAY_SWT coding bit (full ordered recipe in docs/CODING_FSC.md). Coding/FSC writes need your own PSdZData and the toolkit's owner-VIN consent gate; the local mint runs now, the two car-write steps follow the toolkit runbooks.

Extras

Add-ons

Community head-unit add-ons installed over the SSH you enabled — Android Auto, the AA main-menu tile, iDrive Plus info pages, EntryNav2 AA. Each installs from that project's own release files you stage in a kit folder. The installer checks the connected unit's type and prerequisites and refuses to install to the wrong head unit. Non-commercial / community use; full credits in NOTICES.md.

Step 6

Finish & secure

Note the backup path shown in Status. Then restart iDrive (hold the volume/power knob ~30s while parked) and check the apps and CarPlay. Finally, close SSH so the unit isn't left open as root.

Leaving root SSH open on a customer's car is a standing risk. Close it once you've verified everything.
